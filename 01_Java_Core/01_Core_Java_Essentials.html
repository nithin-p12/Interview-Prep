3. equals, hashCode & immutability

3.1

The equals / hashCode contract

toggle the overrides, add two equal users to a HashSet
set.size() 0last contains() —

The contract

  1. a.equals(b) ⇒ a.hashCode() == b.hashCode()
  2. Same hashCode does not mean equal (collisions are fine)
  3. Override both or neither, using the same fields

Remember: a HashSet/HashMap first jumps to a bucket by hashCode(), then checks equals() inside it. Break either and lookups silently fail.

3.2

Make a class immutable

tick the rules — see which attacks still work

Remember: immutable = state fixed after construction. Free thread-safety, safe as map keys, safe to share and cache. Since Java 16 a record + List.copyOf gives you most of this in one line.

5. All in action

5.1

Predict the output

guess first — the answer and the why appear after you click
Integer a = 127, b = 127;
Integer c = 128, d = 128;
System.out.println((a == b) + " " + (c == d));
127 comes from the Integer cache (same object); 128 creates two objects. 1.2
System.out.println(1 + 2 + "3" + 4 + 5);
Left to right: 1+2 = 3 (numbers), then "3"+"3" → "33", then string concat → "3345".
String a = "hi";
String h = "h";
String c = h + "i";
System.out.println(a == c);
h isn't a constant, so h + "i" runs at runtime → new heap object. Make it final String h and it's true (compile-time constant). 2.1
static void swap(Integer x, Integer y) {
    Integer t = x; x = y; y = t;
}
Integer a = 1, b = 2;  swap(a, b);
System.out.println(a + "," + b);
Pass-by-value: only the copies x, y are swapped. You can't write a swap method in Java. 1.1
System.out.println(0.1 + 0.2 == 0.3);
Binary floating point can't store 0.1 exactly (0.30000000000000004). Use BigDecimal for money.
char c = 'A';
System.out.println(c + 1);
char + int is promoted to int: 65 + 1 = 66. Cast back with (char)(c + 1) to get B.
