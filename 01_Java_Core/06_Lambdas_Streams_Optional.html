1. Lambdas

1.1

Which functional interface?

a lambda is just an implementation of one abstract method
r -> r.status() == FAILED
Takes a value, returns boolean → Predicate<Result>. Used by filter.
r -> r.durationMs()
T in, R out → Function<Result, Long>. Used by map.
() -> UUID.randomUUID().toString()
Nothing in, value out → Supplier<String>. Used by orElseGet, generate.
r -> log.info("done {}", r.id())
Value in, nothing out → Consumer<Result>. Used by forEach.
(suite, env) -> new Run(suite, env)
Two inputs, one output → BiFunction<Suite, Env, Run>.
name -> name.trim()
Same type in and out → UnaryOperator<String> (a Function<T,T>).

Remember: a functional interface has exactly one abstract method (@FunctionalInterface just makes the compiler check it). Lambdas can read local variables only if they're effectively final — the value is copied into the lambda.

Good to know Primitive versions (IntPredicate, ToLongFunction…) avoid boxing. A lambda's this is the enclosing object — unlike an anonymous class.
1.2

Method references

click a lambda to shorten it — 4 kinds

Remember: Class::method is shorthand for a lambda that only calls that method. If the lambda does anything else (extra args, a calculation), keep the lambda.

The tricky one — unbound instance

(a, b) -> a.compareTo(b) → String::compareTo
The first parameter becomes the object the method is called on.
Good to know Comparator.comparing(Result::durationMs).reversed().thenComparing(Result::testName) — method refs make sort keys read like English.

2. Streams

2.1

Streams are lazy

guess the print order, then step — elements flow one by one

Remember: intermediate ops (filter, map) only build a recipe; the terminal op (toList, count, forEach) runs it. Each element goes through the whole chain before the next, and limit/findFirst short-circuit.

2.2

Collectors playground

one list of test results, six collectors
Good to know groupingBy returns a HashMap (no order). Need order? groupingBy(f, TreeMap::new, toList()). Downstream collectors: counting, mapping, averagingLong, maxBy.
2.3

flatMap & parallel streams

flatten nested lists · and when NOT to go parallel

Result

Remember: map = one in, one out. flatMap = one in, a stream out, merged into one flat stream. Use it for "all tests across all suites".

results.parallelStream()
       .map(r -> jira.createIssue(r))  // HTTP call
Blocking I/O on the common ForkJoinPool (cores − 1 threads, shared by the whole JVM) starves every other parallel stream. Use your own executor / CompletableFuture.
List.of("smoke", "regression", "sanity")
    .parallelStream().map(String::toUpperCase)
3 tiny elements — splitting and merging costs more than the work.
LongStream.range(0, 50_000_000)
    .map(this::checksum).sum()   // pure CPU
Large, CPU-bound, no shared state, easy to split → a good fit. Measure first.
Good to know parallel + forEach loses order (use forEachOrdered), and lambdas must not modify shared state — no list.add from inside.

3. Optional

3.1

Optional — use it right

click each ❌ to fix it · then try orElse vs orElseGet

Remember: Optional is a return type for "maybe no result" (e.g. findById). Don't use it for fields, parameters or collections (return an empty list instead).

Predict the output

stream & Optional traps
Stream<Run> s = runs.stream();
System.out.println(s.count());
System.out.println(s.count());
A stream can be consumed once: "stream has already been operated upon or closed". Create a new one each time.
Stream.of(1, 2, 3)
      .peek(System.out::println)
      .map(x -> x * 2);
No terminal operation → the pipeline never runs. 2.1
String load() {
    System.out.println("DB hit");
    return "db"; }
Optional.of("cached").orElse(load());
The argument of orElse is evaluated before the call, even when a value is present. 3.1
List<Run> l = runs.stream().toList();  // Java 16+
l.add(newRun);
Stream.toList() returns an unmodifiable list.
List<Run> l = runs.stream()
        .collect(Collectors.toList());
l.add(newRun);
Today it's an ArrayList, so it works — but that's not guaranteed. Use toCollection(ArrayList::new) if you'll mutate.
int failed = 0;
results.forEach(r -> {
    if (r.failed()) failed++;
});
failed isn't effectively final. Use results.stream().filter(Result::failed).count(). 1.1
