Remember: ArrayList wins almost every real case — elements sit next to each other, so the CPU cache loves it. Need fast add/remove at both ends? Use ArrayDeque, not LinkedList.

Good to know ArrayList grows by 1.5× when full. If you know the size (e.g. 500 test results), use new ArrayList<>(500).

2.1

Which order do I get back?

HashSet

order of the hash buckets — looks random, can change after a resize

LinkedHashSet

insertion order (a linked list runs through the entries)

sorted (red-black tree) — O(log n), no null

Remember: HashSet = fastest, no order. LinkedHashSet = insertion order (great for de-duplicating tags while keeping the user's order). TreeSet = sorted, plus first(), ceiling(), headSet().

Good to know Sets use equals/hashCode (Hash*) or compareTo/compare (Tree*) to decide "duplicate". A broken equals → duplicates slip in (page 01, 3.1).

Queue, stack, priority

Remember: use ArrayDeque for both queues and stacks (the old Stack class is synchronized and legacy). PriorityQueue is a min-heap: poll() gives the smallest — but printing or iterating it is not sorted.

Good to know offer/poll/peek return false/null when they can't act; add/remove/element throw. For producer–consumer between threads use a BlockingQueue (page 09).

3.2

Removing while iterating

remove every "flaky" test — try each approach
not run

Why "fail-fast"?

Every ArrayList/HashMap keeps a modCount. The iterator remembers it; if the list changes behind its back, the next next() throws ConcurrentModificationException. It happens in one thread too — it's a bug detector, not a thread-safety feature.

Remember: remove with removeIf(...) or iterator.remove(). For lists many threads read while a few write (e.g. listeners), CopyOnWriteArrayList iterates a snapshot and never throws.

Predict the output

classic collection traps
List<Integer> l =
    new ArrayList<>(List.of(10, 20, 30));
l.remove(1);
System.out.println(l);
remove(int index) wins over remove(Object). To remove the value: l.remove(Integer.valueOf(1)).
List<String> l = List.of("a", null);
System.out.println(l);
List.of, Set.of, Map.of reject nulls. 3.3
int[] a = {1, 2, 3};
System.out.println(
    Arrays.asList(a).size());
Generics can't hold int, so it's a List<int[]> with one element. Use Integer[] or IntStream.
Set<String> s = new TreeSet<>(
    Comparator.comparing(String::length));
s.add("smoke"); s.add("login");
System.out.println(s.size());
TreeSet treats compare == 0 as duplicate — both have length 5. Keep comparators consistent with equals.
var pq = new PriorityQueue<Integer>();
pq.add(3); pq.add(1); pq.add(2);
System.out.println(pq);
toString shows the internal heap array — not sorted. Only poll() gives 1, 2, 3. 2.2
List<String> l = new ArrayList<>(
    List.of("a", "b", "c"));
for (String s : l)
    if (s.equals("b")) l.remove(s);
System.out.println(l);
Removing the second-to-last element makes hasNext() return false — the loop ends before the check. A bug that hides in tests. 3.2
