Spot the violation

which letter does each snippet break?
class SuiteService {

Single responsibility: running, reporting and emailing change for different reasons — split them.
switch (channel) {
  case "EMAIL" -> sendEmail(r);
  case "SLACK" -> sendSlack(r);
  // edit here for every new channel
}
Open/closed: a new channel should be a new class, not an edit to tested code.
class Square extends Rectangle {
    void setWidth(int w) {
        super.setWidth(w); super.setHeight(w);
    }
}
Liskov: code that sets width then height on a Rectangle breaks when given a Square — the subtype changes the promised behaviour.
interface Reporter {
    String html(); byte[] pdf(); byte[] excel();
}
// ConsoleReporter only needs html()
Interface segregation: clients shouldn't depend on methods they don't use — split into small interfaces.
class RunService {
    private final MongoRunRepository repo =
        new MongoRunRepository();
}
Dependency inversion: depend on a RunRepository interface and inject it (Spring does this) — then tests can pass a fake.

4. All in action

4.1

Predict the output

polymorphism traps interviewers love
class A { String name = "A"; String get() { return name; } }
class B extends A { String name = "B"; String get() { return name; } }
A x = new B();
System.out.println(x.name + x.get());
Fields are not polymorphic — x.name uses the declared type A. Methods are — get() runs B's. 1.2
class A { static String who() { return "A"; } }
class B extends A { static String who() { return "B"; } }
A x = new B();
System.out.println(x.who());
Static methods are hidden, not overridden: chosen by the reference type at compile time.
void p(Object o) { System.out.println("Object"); }
void p(String s) { System.out.println("String"); }
p(null);
Overloading picks the most specific match — String is more specific than Object. (Add p(Integer) and it's ambiguous → compile error.)
class Base { Base() { init(); } void init() {} }
class Child extends Base {
    String msg = "ready";
    @Override void init() { System.out.println(msg); }
}
new Child();
Base's constructor runs before Child's fields are set, yet calls the overridden init() → prints null. Never call overridable methods from a constructor.
