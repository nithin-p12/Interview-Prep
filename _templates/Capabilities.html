3. Simulators



 
3.1
Circuit breaker state machine
Cost · Highgood for: resilience, anything with states

 

  

   
   
sliding window (last 6)

  

  

   

   

   
Remember: CLOSED counts failures in a sliding window → OPEN rejects instantly (fallback) → after a wait, HALF_OPEN lets a few trial calls through to decide. Resilience4j: failureRateThreshold, waitDurationInOpenState, permittedNumberOfCallsInHalfOpenState.

  

 






 
3.2
Token-bucket rate limiter
Cost · Highgood for: live, time-based behaviour

 

  

   

   
refilltraffic

   

   

  

  

   

   
Tokens refill continuously up to the capacity. Each request takes one; with none left → 429 Too Many Requests. A full bucket allows a burst, the refill rate caps the average.

    7. Token cost
    

    
 
    7.1
    What costs more tokens to generate
    rough multiplier vs one plain text slide
    
 
    
  
    
   
    Kind of slideCostWhy
    
   
    Text boxes, tables, Q&A list1×only content; engine does the rest
    
   
    Predict cards, flashcards, fill-blanks, terminal playback1.5×shared widgets — you pay for the questions, not the code
    
   
    Steppers, code-line highlighting, diff viewer2×steps must be authored line by line
    
   
    Looping SVG animations, sequence diagrams3×coordinates, timing, pause/speed, layout fixes
    
   
    Drag-and-drop, palette, read-aloud timer3×event handling; cheap once made shared
    
   
    Bespoke simulators (circuit breaker, thread pool, GC)4–6×state rules + edge cases + many clicks to verify
    
   
    Canvas live charts, pan/zoom maps4–5×sizing, DPR, events; most audit fixes land here
    
   
    Fit / screenshot check loop+30–50%per page; each overflow fix means another run
    
  
    
  
    
   
    Spend tokens well
      
    
    • One star simulator per page, the rest predict cards, steppers and Q&A
      • 
    
    • Ask for content-only edits ("rewrite 2.1 text") — no re-layout
      • 
    
    • Batch similar pages in one go; they share widgets and checks
      • 
    
    • Promote a widget to _shared once it's used twice — then it costs ~1×
      • 
    
    • Give the exact topic list; exploring options costs more than building
      • 
    
    • Re-audit only the pages that changed
    
   
    This page ≈ 20 demos ≈ 2–3 normal study pages of tokens. A typical study page (10 slides, 1–2 simulators) is the sweet spot.
