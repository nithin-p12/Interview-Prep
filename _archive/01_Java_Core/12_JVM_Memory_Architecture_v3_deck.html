6. JIT

6.1

Interpreter → tiered JIT

try it: call a method until it gets hot

▶ Try it — call orderTotal()

Why tiers?

The interpreter starts instantly but is slow. C1 compiles quickly with light optimisation and collects profiles. C2 uses those profiles for aggressive, speculative optimisation. Compiled code goes to the Code Cache.

Remember: usual path 0 → 3 → 4 · trivial methods 0 → 1 · if a speculative assumption breaks, deoptimise back to the interpreter. (Thresholds here are simplified.)

6.2

What the JIT optimises

the big three for interviews

Inlining

copies a small method's body into the caller → no call overhead, opens more optimisations

Escape analysis → scalar replacement

an object that never leaves the method isn't allocated on the heap at all — its fields become locals

OSR (on-stack replacement)

a long-running loop is swapped to compiled code while it is still running

Also

loop unrolling · intrinsics (e.g. Math, String ops) · dead-code elimination

7. GC

7.1

GC roots & reachability

click an arrow to cut a reference, then Mark and Sweep

▶ Try it

GC roots — where tracing starts

  • locals & operands in thread stacks
  • static fields (via loaded classes)
  • JNI references, JVM internals

Reference strength (not roots)

Strong never cleared · Soft cleared under memory pressure · Weak cleared at next GC · Phantom post-mortem cleanup
Objects reachable from a root are live; everything else is garbage — even if they point to each other.
7.2

The G1 cycle

young-only → marking → mixed → back

▶ Try it

1
Young GCsSTW · evacuate Eden + Survivor regions
2
Old ≥ IHOP (≈45%) → Concurrent Startpiggybacks on a Young GC
3
Concurrent Markapp keeps running while live objects are marked
4
Remark → Cleanupshort STW · choose old regions with the most garbage
5
Mixed GCsyoung + some old regions, then back to young-only
6
Full GC — fallback onlyevacuation ran out of space → whole heap, long STW pause

Remembered sets & write barriers

a write barrier records cross-region references in each region's remembered set, so a Young GC scans roots + RSets instead of the whole old generation

Remember: G1 flags: -XX:MaxGCPauseMillis=200, -XX:InitiatingHeapOccupancyPercent. System.gc() is only a hint.
