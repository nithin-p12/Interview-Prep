1. Launch

1.1

java -jar — the JVM starts

everything begins with one command

The OS starts a JVM process with your options. The JVM boots, the Bootstrap class loader loads the core JDK (java.base), and -jar tells it: "open this jar and read its MANIFEST.MF to find the class to run."

▶ Try it — build the command

    Remember: JVM options go before -jar, application arguments go after the jar name.

    What happens inside, in order

    OS starts JVM process→heap & threads set up→Bootstrap loads java.base→open the jar→read MANIFEST.MF
    1.2

    MANIFEST.MF & JarLauncher

    how a "fat jar" finds your main class

    A Spring Boot jar is a fat jar: your code plus every dependency jar inside it. Plain Java can't load nested jars, so Main-Class is Spring's JarLauncher, which then calls your Start-Class.

    notification-service.jar ├─ META-INF/MANIFEST.MF ← read first ├─ org/springframework/boot/loader/… ← JarLauncher ├─ BOOT-INF/classes/ ← your code + application.yml └─ BOOT-INF/lib/ ← dependency jars ├─ spring-boot-4.0.2.jar └─ … 120 more dependency jars

    Remember: Main-Class = JarLauncher (Spring's) · Start-Class = your class. The jar is built by spring-boot-maven-plugin (repackage).

    2.3

    The ApplicationContext is created

    an empty container, then refresh() fills it

    Spring prints the banner and creates the container. For a web app it is a ServletWebServerApplicationContext. Inside sits a BeanFactory with two shelves: bean definitions (recipes) and singleton beans (the real objects). Both are empty at this point.

    The stereotype annotations

    @Componentgeneric Spring-managed class
    @Servicebusiness logic (same as @Component, clearer intent)
    @Repositorydata access + translates DB exceptions to Spring's DataAccessException
    @Controllerweb controller returning views
    @RestController@Controller + @ResponseBody → returns JSON
    @Configurationholds @Bean methods (next slide)

    Remember: scanning creates definitions (recipes), not objects. A class without an annotation, or outside the base package, is ignored.

    3.2

    Your @Configuration and @Bean

    for classes you can't annotate

    You can't put @Component on a third-party class (a WhatsApp SDK, a RestClient). Instead, write a @Bean method that builds it; Spring registers whatever it returns as a bean.

    @Bean or @Component?

    UseWhen
    @Componentyour own class, simple constructor
    @Beanthird-party class, or needs custom setup (URLs, tokens, builders)

    Remember: @Configuration classes are proxied, so calling one @Bean method from another still returns the same singleton — try it on the next slide.

    3.3

    Why is @Configuration proxied?

    try it: switch proxyBeanMethods and start the context

    email() and digest() both call templates(). Spring subclasses a @Configuration class (CGLIB proxy): a call to a @Bean method first checks the container and returns the existing bean.

    Remember: proxyBeanMethods = false ("lite mode") starts faster, but then inject beans as method parameters instead of calling other @Bean methods.

    3.4

    Auto-configuration

    ready-made beans, only when conditions match

    Spring Boot ships hundreds of auto-configurations, listed in META-INF/spring/…AutoConfiguration.imports. Each one has conditions. They run after your own configuration, so if you defined a bean yourself, the auto-config backs off.

    IoC & Dependency Injection

    the container creates and wires your objects

    IoC (Inversion of Control): you don't call new — the container creates objects. DI (Dependency Injection): each bean gets what it needs passed in, usually through its constructor. Spring builds a dependency graph and creates beans dependencies first.

    6.2

    When startup fails

    read the error, find the step that broke

    Common startup failures

    Error messageCause → fixStep
    Port 8080 was already in useAnother process holds the port → stop it or change server.port
    No qualifying bean of type …Class not annotated / outside the scanned package / its condition failed
    The dependencies of some of the beans form a cycleCircular dependency → split the responsibility, don't hide it
    Failed to configure a DataSourceJDBC driver on the classpath but no URL → add config or exclude DataSourceAutoConfiguration
    Could not resolve placeholder 'whatsapp.token'Property missing for this profile → add it to yml / env / Config Server
    BeanCreationException … nested exception …A constructor or @PostConstruct threw → read the last "Caused by" line first

    Remember: Spring Boot prints an APPLICATION FAILED TO START box with a "Description" and an "Action" — read that before the stack trace.
